# Live validation and discovery contract

The collector uses public Polymarket metadata and market WebSockets. Accounts, credentials, funds and orders are unnecessary. CLOB REST metadata/book access returned HTTP 403 on this Mac and was stopped. Gamma metadata and public WebSockets are accessible; these are distinct documented public services, not a retry of the denied CLOB path.

## Catalog scope

The default `/markets/keyset` walk discovers markets directly. A full traversal can take tens of minutes. The optional `/events/keyset` walk flattens embedded markets; a subsequent bounded audit found standalone candidates absent from that query, so it is a diagnostic alternative. Both request v1 and v2, follow dependent opaque cursors to a terminal page, reject cursor loops and publish no prefix as a completed sweep. With `--audit-catalog`, each completed event traversal is checked against one standalone market page; sampled omissions reject publication. This is a bounded cross-check, not a full independent reconciliation. A full event traversal is not independent proof that every exchange market is attached to an open event. CLOB catalog reconciliation could not be performed because access was denied. Standalone market traversal is slower; its earlier 600-second run did not reach a terminal page.

Each page has four attempts at the same cursor; exhausted transient attempts retain the catalog checkpoint and retry that cursor with capped backoff, and numeric Retry-After support for 429. 401/403 are terminal without retry. Pages are bounded to 32 MiB; an oversized page reduces the requested page size at the same cursor. Page payloads are discarded after processing. Individual malformed market records are quarantined, sampled and counted; previous assets are retained by market ID. Unknown-ID records defer destructive removals and report that count, preserving uncertainty. A later sweep is delayed until the prior one completes; sweeps do not overlap.

Canonical IDs are version-specific: v1 uses only JSON `clobTokenIds`; v2 uses only `positionIds`. Explicit ineligibility excludes a record. Nullable flags produce provisional candidates. Missing IDs remain unresolved and retain prior assets. Unresolved counts are never converted to fictitious ready symbols. Snapshot receipt proves observed book availability, not metadata truth or complete history.

## Connections and validity

Automatic shard sizing targets 128 base sockets, with one primary replica by default; `--replicas 2` enables an independent standby and a separate 128-base-socket guard. Each shard may additionally own one warm replacement, with at most four globally. Connection attempts are globally paced at least 500 ms apart. One FIFO budget allows at most one subscription request (at most 100 IDs) every 25 ms across base, warm and maintenance traffic; sockets continue reading while waiting. New subscriptions/refreshes pause awaiting application-PONG progress, independently of data-based transport liveness. Plain PONGs carry no sequence IDs: any observed application PONG releases the barrier, preventing permanent debt after an omitted reply. A stalled new-subscription ramp recovers its source after 180 seconds without progress, staggered by replica. Bounded stall diagnostics report the state. Subscribe/unsubscribe frames carry at most 100 IDs and are spaced 1 second apart while reads/heartbeats continue. Universe changes update existing sockets. Duplicate lifecycle broadcasts are discarded before expensive work; genuine hints add only new engine symbols and update affected shard watches.

Quiet markets retain their initialized books while the source connection is healthy. Valid book activity feeds silence/rate-drop monitoring. Maintenance refreshes at most 100 assets per 30 seconds on the existing socket; silence requests verification rather than expiring a book by age. A queued verification preserves the healthy book. Only after its rate-budget grant, immediately before writing unsubscribe, does the affected replica reset; restore is permitted while PONG progress is delayed. Staggered rotation opens a warm replacement before closing the old source. Frozen outgoing watermarks captured at ramp completion prevent a moving promotion target. Its 120-second snapshot grace begins after the actual paced subscription ramp completes, so dial, global-budget and PONG waits cannot consume it. A separate conservative ramp deadline (at least 15 minutes, scaled for the global budget) prevents an unfinished ramp from retaining a warm slot forever. Failed warmup preserves the old source and backs off exponentially, capped at 30 minutes. Inbound application data establishes transport liveness even when PONG is queued; per-symbol book progress remains separate. Absence of data/replies triggers reconnection. Older full dumps cannot replace a newer maintained book. Promotion always emits a complete watermark-safe snapshot before subsequent deltas.

## Reproduce bounded validation

After `cargo build --release --locked`:

```sh
# Short bounded diagnostic; it may finish before a full catalog walk.
python3 scripts/validate_live.py --seconds 900 --report-dir evidence/live-run
# For a large universe, after checking available memory/disk:
python3 scripts/validate_live.py --seconds 4500 --rss-limit-mib 6144 --output-limit-mib 8192 --audit-catalog --rotate-secs 300 --report-dir evidence/live-large
```

The foreground validator records exact PID/start/stop metadata, owns/reaps its collector, decodes real aligned SBE output through the supplied reader and removes temporary output. Default caps are 1.5 GiB RSS / 256 MiB output; explicit maxima are 6 GiB / 8 GiB. Runtime includes discovery. Resource-cap exits are successful cleanup, not coverage success. No full-universe claim follows from merely finishing discovery.

Reports separate candidates, initialized and redundant-ready books, reconnect causes and decoded snapshot-batch sizes. Minute logs identify exact receipt timestamps, universe, emitted, missing and duration. Minute logs include the zero-based output record start and exclusive end. The validator uses those ranges to check decoded counts and lexical order without confusing coincident stream snapshots. Older logs use timestamp cohorts and explicitly label their ambiguity. It retains no per-minute universe-sized diagnostic sets. The log's actual timer/health records and local 61-second timer test provide additional context. Exchange-to-receive differences include old snapshot timestamps and clock skew, not one-way network latency.

Official schema does not define `ready`/`funded` as snapshot-availability predicates, and publishes no numeric per-connection asset cap. These fields are not used to shrink the readiness denominator. `initial_dump` is documented for initial subscription; dynamic refresh snapshot behavior must be established through live observations, not assumed from local fixtures. A new physical connection always requires an observed snapshot before deltas. See SOURCES.md.
